# Architecture Diagram

[`aws-architecture.svg`](./aws-architecture.svg) /
[`aws-architecture.png`](./aws-architecture.png) — also linked from the root
`README.md`. It describes what this repository actually provisions, not a
reference design.

## What it shows

- **GitHub Actions → AWS over OIDC, no static keys.** CI builds and pushes on
  GitHub-hosted runners; CD runs on a self-hosted runner registered on the
  k3s control-plane instance, so the Kubernetes API is never exposed and no
  kubeconfig is stored as a secret.
- **VPC `10.0.0.0/16`** across 2 availability zones:
  - public subnets `10.0.0.0/24` and `10.0.1.0/24` — the ALB and the NAT
    instance, and nothing else
  - private subnets `10.0.10.0/24` and `10.0.11.0/24` — the k3s nodes and RDS
- **Internet Gateway** for the public tier, and a **NAT instance** (a
  `t3.micro`, not a billed NAT Gateway) as the only outbound path for the
  private tier.
- **Self-managed k3s on EC2**: one control-plane instance plus an Auto Scaling
  Group of workers, all in private subnets with no public IPs and no SSH
  keys. Access is `aws ssm start-session` only.
- **Application Load Balancer** in the public subnets across both AZs,
  forwarding to **NodePort 30080** on every node, where **Traefik** (bundled
  with k3s) does path-based routing to the four ClusterIP Services.
- **orders-service → catalog-service** over cluster DNS, so the call never
  leaves the cluster or passes through the load balancer.
- **Amazon RDS PostgreSQL** in the private subnets via a DB subnet group,
  reachable only from the cluster security group. Each of the three services
  owns its own schema in the one database.
- **4 ECR repositories** — one per component, tags immutable, images tagged
  by commit SHA.
- **S3** for Terraform remote state, with a DynamoDB table for state locking.

## Where the diagram is deliberately simplified

- **Backups are RDS-native, not S3.** The `rds` module sets
  `backup_retention_period = 7` and a nightly `backup_window`, which is
  automated RDS snapshots. Nothing in this project ships database dumps to
  S3; the S3 bucket in the diagram holds Terraform state only.
- **Secrets are not drawn.** The RDS master password lives in Secrets
  Manager, generated by AWS and never seen by Terraform. The JWT signing key
  shared across the three services and the initial admin password live in SSM
  Parameter Store as SecureStrings, generated on the first deploy. The k3s
  join token is a SecureString in SSM too.
- **The listener is plain HTTP.** HTTPS needs a certificate, which needs a
  domain, and an ALB's generated DNS name cannot hold an ACM certificate.
  With a domain this becomes a redirect to a 443 listener and
  `COOKIE_SECURE` flips to `true` in auth-service. See the `tfsec:ignore`
  note in `terraform/modules/alb/main.tf`.
- **Single-AZ RDS.** Multi-AZ doubles the cost and is outside the free tier,
  so `db_multi_az` defaults to `false` — while the subnet group still spans
  two AZs, because RDS requires it.
